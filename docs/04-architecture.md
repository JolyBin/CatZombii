# 04 — Архитектура

*Срез: 2 августа 2026, сверен с кодом после `a453a080`, `d162c4db`, `fa1b425a`, `2e6d1bb4`.*

## Главный принцип

**MonoBehaviour только для View и единственной точки входа. Вся логика — обычные
C#-классы (POCO), связанные конструкторами и событиями.**

Это выдержано последовательно почти везде и является главной причиной, по которой
проект расширяем. Единственное исключение — `UIService`, который является
MonoBehaviour-синглтоном (см. ниже).

## Дерево владения

```
GameManager  (MonoBehaviour на объекте Main Camera, единственная точка входа)
│  _uiService, _startBook, _currentLevels[]
│
└─ HomeController                          главный экран, хранит _configIndex
   │
   ├─ HeroController                       выбор героя
   │   └─ EquipmentController              просмотр книги
   │
   └─ StepsController                      ОДНА ПАРТИЯ (создаётся на каждый бой)
      │
      ├─ WorldClock                        ЧАСЫ МИРА — единственный источник времени
      │   ▲ MoveCommand (перелив)   ▲ OnBrewCommand (варка)   ← два действия игрока
      │   └─ Tick() ─► TableController.Tick() ─► BattleController.Tick()
      │
      ├─ FlaskController ──────► OnFlaskFull(Element)
      │                                │
      ├─ TableController ◄─────────────┘
      │   │  накапливает элементы, ищет в Table (trie)
      │   └──────────────► OnSuccessfulMerge(BaseSpell)
      │                                │
      └─ BattleController ◄────────────┘
              spell.ApplySpell(battleController, BattleToken)
          │
          ├─ OnAllEnemyDie ──► StepsController.ShowWinWindow
          └─ OnHeroDie ─────► StepsController.ShowLoseWindow
```

Обрати внимание: **связь односторонняя вниз по владению и событийная вверх**.
`FlaskController` ничего не знает про бой. `BattleController` ничего не знает
про колбы. Склейка живёт только в `StepsController`.

То же и с временем: `WorldClock` не знает ни про колбы, ни про котёл, ни про бой —
только про `ITickable`. Кто подаёт ему такт и кому он его раздаёт, решает
`StepsController` (см. «Часы мира» ниже).

## Ключевые решения и их цена

### 1. Trie для поиска комбинаций

[`Table.cs`](../Assets/Scripts/Runtime/Spells/Table.cs) +
[`Chain.cs`](../Assets/Scripts/Runtime/Spells/Models/Chain.cs)

Комбинации книги разворачиваются в префиксное дерево по `Element.ID`.
Поиск — за длину последовательности, независимо от количества комбинаций.

**Почему это правильно:** порядок элементов значим, префиксы естественно
переиспользуются (`Fire` и `Fire > Fire` — разные заклинания, живут в одной ветке),
добавление комбинации не требует перестройки.

**Цена:** дерево строится на каждый `new Table(...)`, то есть на каждый бой.
При текущих объёмах (3–5 комбинаций) это ничто.

### 2. Заклинание = конфиг-ассет + рантайм-объект

```csharp
BaseSpellConfig (ScriptableObject)  →  GetSpell()  →  BaseSpell (POCO)
                                                         │
                                ApplySpell(BattleController, CancellationToken) : UniTask
```

Конфиг хранит данные и живёт в проекте. `BaseSpell` создаётся на применение
и сам знает, что делать с боем. Новое заклинание = один файл + один ассет,
ничего в существующем коде трогать не надо.

`ApplySpell` возвращает `UniTask` и принимает токен жизни боя (`d162c4db`;
раньше был `async void` без токена). Точка запуска одна —
`BattleController.ApplySpell`, обёртка над подпиской на `OnSuccessfulMerge`:
она ждёт задачу, гасит `OperationCanceledException` тихо, а всё остальное
отправляет в `Debug.LogException`. То есть **ошибка внутри заклинания теперь
всплывает** — она видна в консоли и не теряется в WebGL, где при
`Exception Support = Explicitly Thrown Only` исключения из `async void`
глотались молча.

**Цена:** запуск всё ещё fire-and-forget — вызывающий код не ждёт заклинание
и не может по нему что-то решить. Дисциплина переехала внутрь: каждое ожидание
обязано получить токен, иначе эффект переживёт бой. Рецепт —
в [05 — Как расширять](05-extending.md).

### 3. Юнит = конфиг + рантайм + UI-виджет

[`UnitRuntime.cs`](../Assets/Scripts/Runtime/Battle/UnitRuntime.cs) склеивает три вещи:
`Health` (модель), `TargetController` (таймер и выбор цели), `UIUnit` (виджет).

Атака юнита — тоже конфиг-фабрика: `BaseUnitSpellConfig.GetUnitSpell()` →
`BaseUnitSpell.InitSpell(owner, battleController)`, который подписывается
на `owner.TargetController.OnAttack`. Именно так реализованы и обычная атака,
и трёхфазный босс.

### 4. Окна не создаются, а переключаются

[`UIWindow`](../Assets/Scripts/Runtime/Utility/Services/UIService/Realization/UIWindow.cs)
гасит `Canvas.enabled`, а не `SetActive(false)`.

**Почему:** для WebGL это заметно дешевле — не пересобирается иерархия,
не дёргаются `OnEnable`/`OnDisable`, не теряются ссылки.

**Цена:** объекты остаются активными и продолжают получать `Update`.
И — важно — [`UIService`](../Assets/Scripts/Runtime/Utility/Services/UIService/Realization/UIService.cs)
ищет окна через `FindObjectsByType<UIWindow>(FindObjectsInactive.Exclude)`,
то есть **все окна обязаны быть активны на сцене в момент `Awake`**.
`GameManager.Start()` сразу вызывает `HideAll()`.

### 5. Ручное управление подписками через `IAction`

```csharp
public interface IAction { void ClearAction(); }
```

Контроллеры собирают подписчиков в `List<IAction>` и чистят в `Exit()`.
Контроллеры также занулают собственные события (`OnFlaskFull = null` и т.п.).

**Почему так:** проще, и при перезапуске партии всё пересоздаётся заново.

**Цена:** дисциплина держится на человеке. Забыл добавить `ClearAction()` —
получил утечку подписки между боями. Это самое хрупкое место архитектуры.
При добавлении новой подписки **обязательно** ищи соответствующий `Exit()`.
Отдельно опасны подписки лямбдой: снять такую нельзя в принципе, поэтому
обработчики, которые надо отписывать, хранятся в поле или объявляются методом
(как `_applySpellAction` и `HeroDie` в `BattleController`).

### 5а. Отмена: токен партии → связанный токен боя

Подписки `IAction` отвечают за «кто на что подписан», но не за «что уже
запущено и ещё крутится». Для этого с `d162c4db` есть второй, независимый
механизм:

```
StepsController._partyCts          создаётся в Init(), отменяется в Exit()
        │  CreateLinkedTokenSource
        ▼
BattleController._battleCts        отменяется раньше партии: смерть героя,
        │                          победа (EndBattle) или выход
        ▼
BattleController.BattleToken       уходит в ApplySpell — сегодня это единственное
                                   место, где что-то может «продолжаться»
```

Правило простое: **всё, что ждёт, ждёт с токеном боя**. Флаг `_isBattleOver`
дополняет отмену синхронно: он не даёт добавить юнита или засчитать конец волны
уже после конца боя.

**Область действия правила сузилась с `2e6d1bb4`.** Таймеры атаки, стан, тики
регенерации и спавн помощников босса больше не ждут — они считают такты и
останавливаются вместе с миром (`WorldClock.Stop()`), см. «Часы мира» ниже.
Токен нужен ровно двум вещам: единственной оставшейся `async`-цепочке
(`UltPets.ApplySpell`, где токен проверяется между под-заклинаниями) и длящемуся
эффекту, подписанному на `BattleController.OnTact` — `Regeniration` проверяет токен
перед каждым тиком и отписывается сама.

Два механизма не конкурируют: `IAction` разбирает подписки, токен гасит
незавершённую асинхронщину. Добавляешь новое ожидание — тебе нужен токен;
добавляешь новое событие — тебе нужен `ClearAction()`/`Exit()`.

### 6. Часы мира: `WorldClock` и `ITickable`

[`WorldClock.cs`](../Assets/Scripts/Runtime/Steps/WorldClock.cs) (`2e6d1bb4`) —
**единственный источник времени в игре**. Игра пошаговая: такт мира = одно действие
игрока, действий ровно два.

| Действие | Событие | Кто поднимает |
|---|---|---|
| Перелив шарика между колбами | `FlaskController.MoveCommand` | `FlaskController.MoveBall` |
| Варка (кнопка котла) | `TableController.OnBrewCommand` | `TableController.CheckRepit` |

Не двигается игрок — мир стоит. Отсюда цена сортировки: каждый перелив оплачен
ходом соседей, а длинный рецепт дорожает сам, без единого таймера
([10 §0.2](10-progression-design.md)).

```csharp
public interface ITickable { void Tick(); }
```

Реализуют его `TableController` (часы котла), `BattleController` (бой) и
`TargetController` (таймер одного юнита; такт до него доводит `BattleController`).

#### Почему подписки на `MoveCommand` живут в `StepsController`, а не в системах

Котёл и бой **не подписаны на действия игрока напрямую**. Оба конца — и подписка
на два события, и раздача такта — собраны в `StepsController.Init()`:

```csharp
_worldClock = new WorldClock(_tableController, _battleController);
_tickAction = _worldClock.Tick;
_flaskController.MoveCommand   += _tickAction;
_tableController.OnBrewCommand += _tickAction;
_worldClock.Start();
```

Причина ровно одна: **порядок фаз внутри такта не должен зависеть от порядка
подписки**. Multicast-делегат зовёт обработчики в порядке добавления, поэтому при
прямых подписках перестановка двух строк в `Init()` молча меняла бы правила игры —
котёл остывал бы то до, то после хода врагов, и найти это по диффу было бы нечем.
Сейчас порядок виден целиком в одном методе `WorldClock.Tick()` и там же обоснован.

#### Порядок фаз внутри такта

**остывание котла → длящиеся эффекты игрока → враги → союзники**

| # | Фаза | Где | Почему здесь |
|---|---|---|---|
| 1 | Часы котла | `TableController.Tick()` | Остывание — прямое последствие действия игрока над **его же** ресурсом, поэтому разрешается первым: соседи ходят уже по окончательному состоянию котла, а не по промежуточному |
| 2 | Длящиеся эффекты игрока | `BattleController.OnTact` | Игрок уже заплатил за них ходом варки — лечение обязано успеть до удара, от которого его и варили, иначе «сварить лечение на трёх HP» проигрывается всегда |
| 3 | Враги | `BattleController.TickSquad(_enemyList)` | — |
| 4 | Союзники | `BattleController.TickSquad(_friendlyList)` | Враг, доживший до своего удара, обязан ударить в том же такте, в котором игрок сделал ход, — иначе призыв питомца работал бы бесплатным «блоком» уже занесённого удара, а телеграфа у ударов нет |

Фазы 2–4 лежат внутри `BattleController.Tick()`, и весь бой идёт **вторым**, после
котла, по одной жёсткой причине: только бой умеет **закончить партию** (смерть героя,
смерть последнего врага последней волны). После события конца боя внутри такта не
должно происходить ничего — иначе хвост котла отваливался бы уже из-под показанного
окна итога. Отсюда же проверки `_isBattleOver` между фазами и внутри `TickSquad`.

> Обход отряда идёт по снимку (`_tickBuffer`), а не по живому списку: атака убивает
> юнита прямо внутри обхода (`Health.OnDied` → `Remove`).

#### Почему варка не сжигает варящийся рецепт

Такт варки берётся **последним**, уже после награды. `TableController.CheckRepit()`
сначала применяет заклинание (`OnSuccessfulMerge`) и очищает котёл, и только
последней строкой поднимает `OnBrewCommand`. Значит к фазе 1 котёл уже пуст, а к
фазе 2 зелье уже подействовало: такт, которым игрок **платит** за варку, не может
ни сжечь варящийся рецепт, ни убить героя раньше только что выпитого лечения.

Варка стоит такта сознательно. Бесплатная варка убивает то, ради чего пошаговость
и делалась: игрок доливал бы до последнего возможного хода и забирал награду даром.
Провал варки стоит такта тоже — котёл он очищает так же, как успех.

#### Остановка мира

`WorldClock.Stop()` — мир перестаёт принимать действия (`Tick()` выходит сразу).
Зовётся из `StepsController.FinishParty()` вместе с `FlaskController.LockInput()`
и `TableController.LockInput()` на обоих окнах итога. Это и есть закрытая вторая
половина [бага №12](06-known-issues.md): отдельного «замораживателя» пошаговому миру
не требуется — остановить приём действий и значит остановить мир.

#### Единственный множитель конверсии

Длительности прототипа записаны в ассетах в миллисекундах. Переводит их
**одно число** — `WorldClock.MILLISECONDS_PER_TACT = 1000` — через
`TactsFromMilliseconds()` / `TactsFromSeconds()`:

- меньше одного такта не бывает: «ноль тактов» означал бы бесплатное действие,
  то есть возврат к real-time. Ноль на входе — это «не атакует вовсе», он остаётся нулём;
- разнести конкретного врага отдельно от общего множителя можно, не трогая это
  число: у `UnitConfig` есть override `_attackCooldownTacts`.

После замера «переливов на схлопывание» ([10 §8](10-progression-design.md), шаг 0)
правится ровно это число — и все враги, фазы босса и стан переезжают вместе с ним.

### 7. Асинхронность на UniTask

UniTask (не корутины и не `System.Threading.Tasks`) остаётся: он не аллоцирует,
работает на WebGL (где нет потоков) и интегрирован с жизненным циклом плеера.
Сигнатура `ApplySpell(BattleController, CancellationToken) : UniTask` не менялась,
единственная точка запуска — `BattleController.ApplySpell` через `.Forget()`.

**Но игровые длительности больше не живут в `Delay`.** С `2e6d1bb4` в
`Assets/Scripts/Runtime` не осталось ни одного `UniTask.Delay`: кулдауны атак, стан,
интервал регенерации и спавн помощников босса считаются в **тактах мира**. Прежний
цикл `TargetController.TimerAttack()` с шагом 100 мс удалён целиком — вместо него
`Tick()`, приходящий снаружи.

Причина не в производительности, а в правилах: любой `Delay` — это кусок real-time
в пошаговой игре, то есть время, которое идёт, пока игрок не ходит. Каждый такой
таймер — бесплатный ресурс для того, кто просто перестал играть
([баг №17](06-known-issues.md)).

Реального `await` в игровом коде сегодня один — `UltPets.ApplySpell`: он
последовательно применяет под-заклинания, проверяя токен между ними. Отмена, где
она ещё нужна, оформляется как раньше: токен в аргументе и проверка перед действием.

## Жизненный цикл партии

```
StartGame()
  new StepsController(uiService, book, homeController, levelConfig)
     ├─ new FlaskController(...)        ← ещё ничего не показывает
     ├─ new TableController(...)        ← ПОКАЗЫВАЕТ окно стола прямо в ctor
     └─ new BattleController(...)       ← берёт ссылку на окно боя

  stepsController.Init()
     ├─ new CancellationTokenSource()  ← токен партии
     ├─ uiService.Show<UIBattleWindow>()
     ├─ flaskController.Init()          ← создаёт колбы, показывает окно
     ├─ flaskController.SubscribeToMove()  ← ТОЛЬКО ЗДЕСЬ вешаются обработчики
     ├─ battleController.Init(partyToken)  ← связанный токен боя, HP героя, первая волна
     ├─ tableController.Init()
     └─ new WorldClock(table, battle) + Start()  ← часы мира, единственный вход такта
```

**Порядок всё ещё значим**, но уже не смертелен: `TableController` показывает
своё окно в конструкторе, а `FlaskController` — в `Init()`; подписки на колбы
вешаются отдельным вызовом `SubscribeToMove()` уже после `Init()`. Раньше именно
это спасало от `NullReferenceException` в
[`Flask.CheckRepits`](../Assets/Scripts/Runtime/Flask/Flask.cs) (там был
`RepitsCommand.Invoke` без `?.`) — с `d162c4db` проверка на месте, а с `fa1b425a`
вид колбы рисуется по событию модели и от порядка вызовов не зависит.

Конец партии любым исходом — `StepsController.FinishParty()`: останавливает часы
мира и блокирует ввод у колб и котла, после чего показывается окно итога.

Выход из партии — `StepsController.Exit()`: отменяет токен партии, снимает
собственные подписки (включая обе подписки часов мира — `MoveCommand`
и `OnBrewCommand`), гасит окна, зовёт `Exit()` у всех трёх контроллеров,
возвращает на главный экран. Связанный токен боя освобождается внутри
`BattleController.Exit()`, токен партии — сразу после.

## Поток данных: от клика до урона

```
клик по колбе
  → UIFlask.ButtonClickCommand
  → FlaskController.ReactClickCommand(flask)
  → MoveBall: _selectedFlask.PopElement() → flask.PushElement(element)
  → Flask.CheckRepits(): 4 одинаковых?
      → Flask.RepitsCommand(element)
      → FlaskController.OnFlaskFull(element)   + UpdateFlask (перезаполнение)
      → TableController: _currentElements.Add(element), окно показывает элемент,
                         свежий элемент становится хвостом и получает полный запас
  → MoveCommand → WorldClock.Tick()          ← ТАКТ МИРА, следующей строкой
      → TableController.Tick()   остывание хвоста котла
      → BattleController.Tick()  OnTact → враги → союзники

игрок жмёт «проверить»
  → UITableWindow.OnClickCheckCombinationButton
  → TableController.CheckRepit()
  → Table.TryGetSpell(_currentElements.ToArray(), out spellConfig)
      → успех: OnSuccessfulMerge(spellConfig.GetSpell())
      → BattleController: spell.ApplySpell(this, BattleToken)
      → например PowerAttack: battleController.HeroTarget.Health.TakeDamage(25)
      → Health.OnChanged → UIUnit.SetHealth
      → HP <= 0 → Health.Die() → OnDied → BattleController снимает юнита,
                                          освобождает позицию, проверяет конец волны
  → в любом случае: котёл очищается
  → OnBrewCommand → WorldClock.Tick()        ← ТАКТ МИРА, уже ПОСЛЕ награды
```

## Что стоит знать, прежде чем менять

1. **`Element.ID` — ключ trie.** Менять ID существующих элементов = ломать все книги.
2. **Количественные лимиты выводятся из сцены, а не дублируются в коде.** Приём
   один и тот же: код читает длину массива позиций
   (`UIBattleWindow.FriendlyPositionsCount` / `EnemyPositionsCount`,
   `UIFlaskWindow.FlaskPositionsCount`), своего числа не хранит. Раньше константа
   и сцена разъехались и роняли бой
   ([баг №1](06-known-issues.md#1--четвёртый-питомец-роняет-бой), закрыт).
   Заводишь новое ограничение такого рода — заводи его в сцене и читай длину;
   спавн сверх лимита должен вытеснять, а не падать.
3. **`Health.Die()` вызывает `Dispose()`**, который зануляет события прямо во время
   их вызова. Подписчики, добавленные после начала инвока, молча теряются —
   [баг №10](06-known-issues.md), открыт.
4. **Всё, что ждёт, ждёт с токеном боя.** Заклинание или таймер без токена
   переживает бой и продолжает работать на главном экране — это чинили
   в `d162c4db`, см. «Отмена: токен партии → связанный токен боя» выше.
5. **Новая система, живущая во времени, реализует `ITickable` и добавляется
   в `WorldClock` — и не подписывается на `MoveCommand`.** Прямая подписка ставит
   новую систему в очередь по порядку строк в `Init()`, то есть делает порядок фаз
   такта невидимым и случайным; `UniTask.Delay` вместо такта возвращает в игру
   real-time и даёт бесплатный ресурс тому, кто просто перестал ходить
   ([баг №17](06-known-issues.md)). Длящемуся эффекту без юнита-носителя точка
   подключения уже есть — `BattleController.OnTact`. Порядок новой фазы решается
   и обосновывается в одном месте — `WorldClock.Tick()`.
6. **`Book.OnValidate` перезаписывает `_uniqElements`.** Руками это поле править
   бессмысленно — оно пересобирается из комбинаций при любом изменении книги.
